# Security and responsible disclosure

This public repository contains descriptions and reviewed engineering status only; it does not expose the canonical private implementation, signing keys, restricted operations, personal data or release archives.

If you identify a possible vulnerability in HumanPulse software or documents, please contact the project privately using the contact information listed on the [official website](https://humanpulseprotocol.com/) or the [official links directory](https://humanpulseprotocol.com/links). Do not post exploit instructions, credentials, raw biometric or civil identity data in public issues.

This repository is not an independent security-audit report, a security certification, a penetration-testing authorization or a public vulnerability-disclosure program with stated rewards. Coordinated disclosure conditions should be established before external testing of live services.

## Disclosure boundaries

HumanPulse intends to communicate status transparently while minimizing unnecessary publication of sensitive operational architecture, anti-abuse details, key custody, infrastructure secrets, private user data and unpublished release artifacts.

A public documentation repository does not by itself make the underlying private source available or open-source.
